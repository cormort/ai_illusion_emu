AI 回答可靠性鏈（端到端架構）

可信賴的生成結果並非單靠模型參數，而是由邊界界定、資料治理、檢索、生成約束與人工覆核共同保障。

LLM 生成路徑：一棵「每一步重新展開」的機率樹

以下動畫不把 LLM 說成固定決策樹，而是把每一輪的候選 Token 暫時畫成樹。綠色游標代表目前被選中的 Token；選定後，它會併入上下文，下一層候選與機率再從該被選節點重新展開計算。

① 上下文進入模型

提示詞、系統指令與先前 Token 先轉為向量表示。

② 產生 logits

模型對詞彙表中的候選 Token 輸出分數，不是直接輸出完整答案。

③ 解碼選取

Temperature、Top-k、Top-p 等設定改變候選分布與選取範圍。

④ 回饋成新上下文

被選 Token 接回序列，模型再計算下一步，如此反覆生成。

文字 → Token／向量 → Transformer 多層運算 → logits → softmax／解碼 → 選出 Token → 接回上下文

    這個動畫刻意保留的真實機制限制

    不是傳統決策樹：模型沒有預先存在、可完整列出的固定節點與規則；動畫只把每一步機率最高的少數候選視覺化。
    起點也不是隨機根節點：提示詞與對話內容決定初始隱藏狀態。隨機性主要出現在解碼階段，而且 Temperature 為 0 或採 greedy decoding 時可接近確定性選取。
    內部運算不是樹搜尋：Transformer 透過注意力、前饋網路與多層向量運算產生 logits。圖中的連線代表「生成依賴」，不是神經網路內真正的線路。
    畫面只顯示少數候選：真實詞彙表通常有大量 Token；Top-k／Top-p 會截取候選集合，softmax 機率也不等同於知識正確率或可信度。
    幻覺不是單一錯誤節點：錯誤可能來自訓練資料、提示不足、上下文截斷、解碼設定、檢索失敗或模型把語言流暢性誤當作事實依據。

2. 以抽樣或最高機率方式選出一個 Token
3. 從上一層被選中的節點位置展開連線，點亮候選分支與被選路徑

    較精確的一句話：LLM 不是在固定決策樹上找答案，而是根據當前上下文，以 Transformer 計算下一個 Token 的分數，再經解碼規則選出一個 Token；每次選擇都會改變下一輪的條件機率。

    AI 是接字機率計算，而非確定性資料庫檢索

    Token 逐字預測

    語言模型本質是根據前文序列，計算下一個詞元的條件機率分佈 P(w_t | w_1...w_{t-1})。

    機率分佈抽樣

    生成文字通常採用 Top-p 或 Temperature 進行非完全確定性解碼，創造自然多樣的表達。

    溫度與熵

    溫度越高，分佈越平坦（隨機性高）；溫度越低，分佈越陡峭（文字固定），但低溫絕不等於「事實正確」。

    語言模型的輸出流暢性來自語法結構的機率高低，並不代表內容事實曾經受過客觀邏輯或法規勾稽。

    幻覺（Hallucination）的多重誘發機制

    資料外推 (OOD)

    遇到訓練集未涵蓋的專門法規、單位內規或最新事件時，模型缺乏內生記憶。

    自回歸錯誤累積

    前段文字一旦產生微小偏差，自回歸特性會將錯誤視為前提，導致後續整段言之成理地胡扯。

    虛構權威引用

    模型在「文獻格式」上的預測機率極高，因此容易合成看似正規卻完全不存在的條號、函釋或期刊。

    檢索污染與語意錯配

    RAG 檢索時依據語意向量相似度，若檢索回題名相近但標的不同之規定，模型將產生有依據外觀的錯答。

    數值計算薄弱

    自回歸模型對跨段落的四則運算與勾稽天生脆弱，容易出現金額合計數或百分比計算矛盾。

    討好型補全 (Sycophancy)

    在提示詞帶有引導性或誘導前提時，模型傾向迎合提問假設而非駁斥前提。

    兩種不確定性：認知（Epistemic）與偶然（Aleatoric）

    認知不確定性 (外推 X)

    源於「模型知識缺失與外推偏誤」。如同 X > 10，真實規律已發生轉折，模型卻盲目直線外推，此時即使降低溫度，也只是極度自信地給出錯誤答案。必須靠「外掛檢索（RAG）」根治。

    偶然不確定性 (溫度 T)

    源於「解碼隨機抽樣」。高溫會使右圖分佈攤平，紅點機率大增。公務正式文件應調低溫度（如 0.0~0.2）以求結果穩定可重現。

    客觀容許帶 vs 模型預測線

    左圖藍色半透明帶代表客觀真值容許標準；點落在帶外即為紅點。在 X > 10 外推區，模型藍實線偏離客觀綠虛線中心，導致離群率顯著攀升。

    請實際操作觀察：點選左側快速情境「外推／低溫妄斷（X=14, T=0.25）」，可看到抽樣值雖然彼此高度集中，但因為整體預測偏離客觀真值，導致絕大多數點都落在紅線拒絕域內，這正是「精確地出錯（Confidently Wrong）」。

    教學模型之簡化與認知界限

    • 高維 vs 一維： 真實 LLM 參數動輒數十億且處於超高維空間；本工具簡化為 2D 回歸與外推偏誤以利直觀可視化。
    • 連續 vs 離散： 真實詞元（Tokens）是離散的字典機率抽樣；此處以連續常態分佈作為代理。
    • 不可見的訓練邊界： 實務中大模型的「訓練邊界」隱匿在龐大語料中，使用者難以如同圖中 X=10 般一眼辨識是否外推。
    • 統計離群 ≠ 惡意幻覺： 統計學離群值僅為機率極值；實際業務中，有時看似保守合理的文字反而含有重大隱蔽事實錯誤。
    本模擬器用於培養同仁「對生成結果抱持健康懷疑、重視邊界防禦」的心態，非用於測量特定商用模型之客觀錯誤率。

    防範幻覺的「四道安全防線」架構

    第 1 道：邊界約束 (Guardrail)

    在 Prompt 中強制要求：僅依據附件回答，未提及之事項必須明確回答「無相關資料」，嚴禁推論。

    第 2 道：精準錨定 (Grounding / RAG)

    不依賴模型內部記憶，先檢索機關內部現行規定，將權威文本作為上下文提供給模型。

    第 3 道：引用交叉比對

    模型提出結論時必須標註精確條號段落；系統或使用者反向驗證該段落是否確實支持主張。

    第 4 道：規則計算與分級簽核

    數值運算交由 Python/Excel 程式執行，不讓 LLM 做心算；公務公文產出仍由承辦人員負最終責任。

    少樣本範例 (Few-shot)

    在提問中提供標準範例，約束輸出之欄位格式、文句結構與專業用語風格。

    結構化輸出 (JSON/表格)

    要求以標準 Schema 輸出，便於銜接後端檢核程式自動檢查必填項與數值合理性。

    RAG 與防護機制互動實驗室

    步驟 1閱讀問題與文件確認問題核心為「120 萬採購預算是否超過公告金額門檻」。
    步驟 2切換四種情境比較：無檢索、正確檢索、錯誤引用、以及「安全拒答 (Guardrail)」。
    步驟 3核對檢索與引用觀察文件框選狀態與條文內容，確認引用是否真正具備證明力。
    步驟 4評估系統成熟度體會：高成熟度 AI 系統最關鍵的能力是「懂得在無依據時說不知道」。
    四種情境操作與對照重點
    1. 無檢索： 模型在無資料支持下，自行腦補「一般常見門檻」，語氣肯定但具高度風險。
    2. 正確檢索： 檢索到文件 A 第 8 條（公告金額 100 萬），完成「120萬 > 100萬」之正確比較，有憑有據。
    3. 錯誤引用（高隱蔽幻覺）： 系統外表附有引用標籤，但檢索到的是「文件 B 零用金規定」，引注文不對題。
    4. 安全拒答（Guardrail 典範）： 當資料庫缺乏對應規範時，模型明確啟動防護宣告資料不足，拒絕瞎猜。

    操作提示：點選不同情境，觀察回答模式與驗證結果。

    機關公務推動 Generative AI 實踐路徑

    低風險：文句轉換與格式化

    會議發言摘要、公文草擬修辭、Word 轉 JSON、表格格式轉換。效益立竿見影且無重大法律權責外溢風險。

    中風險：跨案彙整與比對

    法案修正草案對照、招標規格初篩、計畫提案重點比較。應落實雙人抽查與引用比對機制。

    高風險：法規裁處與預算核定

    法規適用解釋、預算勾稽、補助資格判定。嚴禁直接採用 AI 輸出，必須全數由專業同仁逐筆查核簽章。

    「以表製表」資料流串聯

    將舊系統雜亂之報表透過 LLM 轉成乾淨結構化資料（CSV/JSON），作為機關新分析儀表板的輸入來源。

    「AI 產製確定性工具」

    讓 AI 撰寫 Python 腳本、SQL 語法或 Excel VBA；執行時使用該確定性程式進行嚴密計算，避開 LLM 心算風險。

    系統膠水層 (System Glue)

    充當跨系統介面轉換工具，減少基層同仁重複人工剪貼騰寫，實現公務作業輕量自動化。

    公務同仁使用生成式 AI 輔助作業，應遵循行政院相關指引，恪守資通安全與機密維護，不得輸入機密公務個資，並由同仁負公文與行政判斷之最終責任。
